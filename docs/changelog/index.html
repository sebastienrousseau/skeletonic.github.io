Changelog

skeletonic.io — 2026-05 site refresh

Documentation site updates that ship alongside library v2.0.0. These are not part of the library bundle — they describe what changed on this site itself.

  • 28 locales. English plus 27 translations (ar, bn, cs, de, es, fil, fr, ha, he, hi, id, it, ja, ko, nl, pl, pt-br, ro, ru, sv, th, tr, uk, vi, yo, zh-hans, zh-hant). Locale switcher in the footer; every page resolves the user's preferred language from <code>Accept-Language</code> if no choice has been saved.
  • Service worker. Cache-first for static assets, network-first with a 3 s timeout for HTML, falling back to the localised <code>/<locale>/offline/</code> page when the network is unreachable.
  • Hero logo. Progressive-enhanced brand mark. The <code>

    </code> text stays in the DOM (text-indent: -9999px) so screen readers, search engines, reader-mode clients, and CSS-disabled visitors still get the page title; CSS swaps the visual to a CDN-served SVG.

  • Lazy search. <code>/js/search-data.json</code> (~51 kB raw / ~10 kB gzip) is fetched only on first ⌘K open. Module-level promise caches the response so subsequent opens are zero-network.
  • CI gates. <code>node scripts/verify-site.mjs</code> runs the same checks CI does, locally: docs build presence, asset 200s, axe-core in light + dark, <code><html lang></code> per locale, service-worker registration, console-error free, mobile Lighthouse 100×4 across every key page.
  • Dark-mode contrast pass. Every component swept under <code>light-dark()</code> and validated against axe-core in both schemes — zero WCAG 2.2 violations across 10 pages × 2 schemes.

v2.0.0 — 2026-05 (current)

The "2026 baseline" major release. Every modern CSS feature that shipped in the 2024–2026 Baseline window is now part of the library's foundation. Class names that consumers were already using are preserved; the underlying tokens, layout primitives, and motion utilities are fundamentally new.

Modern colour system — OKLCH

  • Every brand, status, grey, and keyword colour token migrates from <code>hsl()</code> to <code>oklch()</code>. Perceptually uniform steps from <code>$grey-100</code> through <code>$grey-1000</code>, native wide-gamut (P3) on capable displays, and consistent contrast at every shade.
  • Surface tokens (<code>--background-color</code>, <code>--foreground-color</code>) and <code>prefers-color-scheme: dark</code> overrides are also OKLCH, so dark mode no longer drifts in saturation between light and dark.

Native CSS Cascade Layers

  • <code>skeletonic.styl</code> now declares the layer order at the top:

    <code class="language-css">@layer skeletonic.base, skeletonic.layout, skeletonic.elements, skeletonic.components; </code></pre> 
    Each subtree imports inside its corresponding <code>@layer</code>. Drop an unlayered override anywhere in your project and it always wins — no specificity wars, no <code>!important</code>.

Native CSS Grid — <code>.grid</code>, <code>.grid-cols-N</code>, <code>.col-span-N</code>

  • The legacy <code>.flex-1</code>…<code>.flex-12</code> flexbox grid is replaced with a modern CSS Grid system:

    <code class="language-html"><section class="grid grid-cols-3"> <article class="card">…</article> <article class="card">…</article> <article class="card col-span-2">spans two cells</article> </section> </code></pre> 
    <code>.grid</code> sets <code>display: grid; gap: var(--gr-fsb)</code>; <code>.grid-cols-N</code> generates <code>grid-template-columns: repeat(N, minmax(0, 1fr))</code>; <code>.col-span-N</code> is just <code>grid-column: span N</code>. Less CSS, more layout power, no margin-collapse quirks.

Container queries on <code>.card</code>

  • <code>components/card.styl</code> sets <code>container-type: inline-size</code>. A card's internal layout responds to the card's own width, not the viewport's — so a card that's narrow because it's in a sidebar rearranges itself even on a wide page.
  • Combined with <code>:has()</code> for parent-aware styling (e.g. an <code>.alert</code> that contains a link), this lifts the library to 2026 baseline.

Modern motion utilities

  • <code>src/stylus/utilities/animations.styl</code> introduces:
    • View Transitions API utilities — <code>.view-transition-name-root</code>, <code>-header</code>, <code>-main</code>, <code>-footer</code>, <code>-article</code>, <code>-section</code>. Drop one on each side of an SPA-style page transition and the browser cross-fades or morphs the named element natively.
    • Scroll-driven animation primitives — <code>.scroll-timeline</code> and <code>.animate-on-scroll</code> plug into the native <code>scroll-timeline-name</code> / <code>animation-timeline: view()</code> API.
  • All native, GPU-accelerated, no JavaScript runtime.

Bundle & quality gates

  • Compiled bundle: 38.8 KB raw / 7.7 KB gzip / 6.7 KB brotli — under the 48 / 10 / 8 KB CI ceilings.
  • axe-core gate green: zero WCAG 2.2 violations on the demo page.
  • CycloneDX SBOM updated; npm publish workflow signs and provenances the v2.0.0 tarball.

Migration notes (v1.1.7 → v2.0.0)

  • Colour tokens. The names are unchanged (<code>--cl-primary</code>, <code>--bg-success</code>, <code>$grey-500</code>, etc.) but the resolved values move to OKLCH. Visual output is close to v1.1.7 but not pixel-identical; audit any screenshots in your design system.
  • Grid system. <code>.flex-1</code>…<code>.flex-12</code> is removed. Replace with <code>
    …</code>. See /components/#grid for the new syntax.
  • Spacing utilities. The 12-stop percentage scale (<code>.padding-0</code>…<code>.padding-11</code>, <code>.margin-0</code>…<code>.margin-11</code>) is replaced with a five-step rem-based t-shirt scale: <code>xs</code> / <code>sm</code> / <code>md</code> / <code>lg</code> / <code>xl</code>. So <code>.padding-3</code> → <code>.padding-md</code> (1.62 rem), <code>.margin-bottom-5</code> → <code>.margin-bottom-lg</code> (≈ 2.62 rem). Five steps cover the same visual range with a clearer mental model and saves about 4 KB of compiled CSS. See /spacing/ for the full ladder.
  • Cascade layers. If you had <code>!important</code> overrides to win against Skeletonic, you can almost certainly delete them.

v1.1.7 — 2026-04

The "release-readiness" pass: a11y, supply chain, repo hygiene.

Accessibility (WCAG 2.2) & internationalisation

  • RTL via logical properties — every directional declaration in <code>margin-</code>, <code>padding-</code>, <code>border-</code>, <code>float</code>, <code>text-align</code>, and absolute positioning is now logical (<code>margin-inline-*</code>, <code>inset-inline-*</code>, <code>text-align: start/end</code>, <code>float: inline-start/end</code>). Set <code><html dir="rtl"></code> and the inline axis flips.
  • <code>--gr-h1</code>…<code>--gr-h6</code> heading tokens are now consumed. Previously the <code>

    </code>-<code>

    </code> rules used a separate hand-curated scale and the exported tokens carried unusable Φⁿ values (h1 ≈ 29 rem).
  • <code>$primary</code> / <code>$secondary</code> darkened for AA contrast against white text in buttons / badges / links.
  • Added focus-visible rings on every interactive element.
  • Added <code>@media (prefers-reduced-motion)</code> wrapper around the animations module.
  • Added <code>prefers-color-scheme: dark</code> token swap.

Build & supply chain

  • CycloneDX SBOM generated as part of the npm tarball.
  • <code>size-limit</code> budgets enforced in CI.
  • CVE-2023-44270 (postcss line return) patched via <code>pnpm.overrides</code>.
