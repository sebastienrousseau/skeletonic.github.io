Utilities — Skeletonic Stylus

This documentation is provided in English. A full translation is in progress. <!-- i18n-summary -->

Skeletonic ships a small, opinionated set of utility classes — and every one of them has an equivalent HTML attribute form.

<code class="language-html"><div class="center flex justify-center">…</div> <div center flex justify-center>…</div> </code></pre> 
Both selectors are emitted from the same Stylus source and produce the same CSS rules. Pick whichever your team finds more readable. The attribute form is especially nice for hand-written HTML and AI-generated markup, where extra <code>class=" "</code> quotes add visual noise.
 
 
Layout
 
  
 Class Attribute Effect 
   
 <code>.centered</code> <code>[centered]</code> Fixed-position centred (50%, 50%) 
 
 <code>.center</code> <code>[center]</code> Flex column, items + content centred 
 
 <code>.left</code> <code>[left]</code> Flex column, items + content flex-start 
 
 <code>.right</code> <code>[right]</code> Flex column, items + content flex-end 
  
 
Flexbox
 
  
 Class Attribute Effect 
   
 <code>.flex</code> <code>[flex]</code> <code>display: flex</code> 
 
 <code>.justify-start</code> <code>[justify-start]</code> <code>justify-content: flex-start</code> 
 
 <code>.justify-center</code> <code>[justify-center]</code> <code>justify-content: center</code> 
 
 <code>.justify-end</code> <code>[justify-end]</code> <code>justify-content: flex-end</code> 
 
 <code>.align-start</code> <code>[align-start]</code> <code>align-items: flex-start</code> 
 
 <code>.align-center</code> <code>[align-center]</code> <code>align-items: center</code> 
 
 <code>.align-end</code> <code>[align-end]</code> <code>align-items: flex-end</code> 
 
 <code>.direction-vertical</code> <code>[direction-vertical]</code> <code>flex-direction: column</code> 
 
 <code>.direction-horizontal</code> <code>[direction-horizontal]</code> <code>flex-direction: row</code> 
  
 
Text alignment & casing
 
  
 Class Attribute Effect 
   
 <code>.text-start</code>, <code>.text-left</code> — <code>text-align: start</code> (RTL-aware) 
 
 <code>.text-center</code> — <code>text-align: center</code> 
 
 <code>.text-end</code>, <code>.text-right</code> — <code>text-align: end</code> (RTL-aware) 
 
 <code>.text-uppercase</code>, <code>.uppercase</code> <code>[uppercase]</code> <code>text-transform: uppercase</code> 
 
 <code>.text-lowercase</code>, <code>.lowercase</code> <code>[lowercase]</code> <code>text-transform: lowercase</code> 
 
 <code>.capitalized</code> <code>[capitalized]</code> <code>text-transform: capitalize</code> 
 
 <code>.italic</code> <code>[italic]</code> <code>font-style: italic</code> 
  
 
Sizing
 
  
 Class Attribute Effect 
   
 <code>.size-full-width</code> — <code>width: 100%</code> 
 
 <code>.size-full-height</code> — <code>min-height: 100vh</code> 
 
 <code>.size-full</code> — both — full viewport 
  
 
Box reset
 
  
 Class Attribute Effect 
   
 <code>.nomargin</code> <code>[nomargin]</code> <code>margin: 0</code> 
 
 <code>.nopadding</code> <code>[nopadding]</code> <code>padding: 0</code> 
  
 
Border radius
 
All values use the golden-ratio constant (<code>var(--gr) ≈ 1.62rem</code>).
 
  
 Class Attribute Effect 
   
 <code>.radius</code> <code>[radius]</code> All four corners rounded 
 
 <code>.radius-top</code> <code>[radius-top]</code> Top two corners only 
 
 <code>.radius-bottom</code> <code>[radius-bottom]</code> Bottom two corners only 
  
 
Visibility
 
  
 Class Attribute Effect 
   
 <code>.hidden</code> <code>[hidden]</code> <code>display: none</code> (also matches the native HTML <code>hidden</code> attribute) 
  
 
Spacing — physical and logical
 
The spacing utilities follow a five-step golden-ratio scale (<code>xs</code>, <code>sm</code>, <code>md</code>, <code>lg</code>, <code>xl</code>). See the spacing ladder for each step's resolved value. Logical (<code>-start</code>, <code>-end</code>) forms auto-flip in <code><html dir="rtl"></code>.
 
<code class="language-text">.padding-{size} .margin-{size} .padding-top-{size} .margin-top-{size} .padding-bottom-{size} .margin-bottom-{size} .padding-start-{size} .margin-start-{size} ← logical (RTL-aware) .padding-end-{size} .margin-end-{size} ← logical (RTL-aware) .margin-auto ← centring helper </code></pre> 
Where <code>{size}</code> is <code>xs</code> / <code>sm</code> / <code>md</code> / <code>lg</code> / <code>xl</code>. So <code>.padding-start-md</code> produces <code>padding-inline-start: 1.62rem</code> and auto-flips to <code>padding-inline-end</code> when the container's writing direction is RTL.
 
Group / clearfix
 
  
 Class Effect 
   
 <code>.group</code> Adds a <code>::after</code> clearfix pseudo-element 
  
 
 
Why class and attribute selectors?
 
Three reasons:
 
     
  1. Authoring readability. <code>
    </code> is shorter and easier to scan than <code>
    </code>. For pages with many utility-driven elements, the attribute form keeps <code>class</code> free for semantic state classes.
    2.  
  2. AI-generated HTML. LLMs produce attributes more reliably than long <code>class=" "</code> lists. Attributes are harder to typo.
    3.  
  3. No runtime cost. Both forms compile to the same selectors in the same CSS rules — no JavaScript, no preprocessor toggles. Pick either or both, freely mix.
    4.  
 
The attribute selectors are valid HTML — they are custom data attributes in the HTML5 sense. They render correctly, they round-trip through <code>outerHTML</code>, and they don't trigger any validator warnings.
