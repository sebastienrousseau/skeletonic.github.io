Inputs

Interactive elements the visitor clicks, taps, or focuses to drive the page.

Buttons

A semantic, themable action trigger. Solid and outline variants ship six brand colours each.

Accessibility note. Every <code>.button</code> variant ships with a <code>:focus-visible</code> ring and a 24×24 px minimum hit area (WCAG 2.2 SC 2.5.8). Use <code>&lt;button type="button"&gt;</code> for in-page actions and <code>&lt;a href&gt;</code> only for navigation.
 
 
Button shapes
 
The <code>.btn</code> family is a parallel shape system on top of the <code>.button</code> colour family. Use it when you want a square, round, or oval icon button instead of the default pill.
 
<code class="language-html"><button type="button" class="btn">Square</button> <button type="button" class="btn btn-round">●</button> <button type="button" class="btn btn-oval">Oval</button> <button type="button" class="btn btn-outline">Outline</button> </code></pre> 
 
     
 
 
 
When to use. <code>.btn-round</code> makes a 60×60 px circular button — ideal for a single-character icon (close, like, share). <code>.btn-oval</code> is a softer pill for short verbs ("Buy", "Send"). <code>.btn-outline</code> reads as a secondary action — pair it with a solid <code>.btn</code> for the primary call to action.
 
 
Button groups
 
Use <code>.button-group</code> to render a set of related buttons as a single visual unit. <code>.block</code> makes a single button stretch full-width — handy for forms on narrow viewports.
 
<code class="language-html"><div class="button-group"> <a href="#" class="button primary">Save</a> <a href="#" class="button secondary">Save as draft</a> <a href="#" class="button warning">Discard</a> </div> <a href="#" class="button primary block">Full-width call to action</a> </code></pre> 
 
 Save Save as draft Discard 
 
 Full-width call to action 
 
 
 
Accessibility note. Wrap a button group in <code>role="group"</code> with an <code>aria-label</code> describing what the buttons do together (e.g. "Document actions"). Without that, assistive tech announces each button as if it were unrelated.
 
 
Badges
 
A compact label for status, count, or category. Text size is fixed so badges align with surrounding text.
 
<code class="language-html"><span class="badge">Default</span> <span class="badge primary">Primary</span> <span class="badge success">Success</span> <span class="badge warning">Warning</span> <span class="badge danger">Danger</span> </code></pre> 
 
 Default Primary Success Warning Danger 
 
 
 
Accessibility note. Badges are decorative by default. When the badge carries the only signal (e.g. an unread count), wrap it in a visually-hidden helper: <code>3 unread messages</code>.
 
 
 
Feedback
 
Surfaces that tell the visitor something happened — or is about to happen.
 
Alerts
 
Status messages with semantic intent. In v2.0.0 every variant is explicitly namespaced under <code>.alert-{primary,secondary,info,success,warning,error}</code> so the variant class cannot collide with state classes elsewhere on the page.
 
<code class="language-html"><div class="alert alert-primary" role="alert"> <strong>Heads up.</strong> This is a primary alert. </div> <div class="alert alert-success" role="status"> <strong>Saved.</strong> Your changes are persisted. </div> <div class="alert alert-warning" role="alert"> <strong>Careful.</strong> This action affects shared state. </div> <div class="alert alert-error" role="alert"> <strong>Error.</strong> Could not save the form. </div> </code></pre> 
 
 Heads up. This is a primary alert. 
 
 Saved. Your changes are persisted. 
 
 Careful. This action affects shared state. 
 
 Error. Could not save the form. 
 
 
 
Accessibility note. Use <code>role="alert"</code> for messages that demand immediate attention (errors, warnings) and <code>role="status"</code> for non-urgent confirmations. Both expose the message to assistive tech the moment it appears.
 
 
Code blocks
 
<code>&lt;code&gt;</code>, <code>&lt;kbd&gt;</code>, <code>&lt;pre&gt;</code>, and <code>&lt;samp&gt;</code> get monospace styling and a thick inline-start accent stripe (which flips automatically under <code>&lt;html dir="rtl"&gt;</code> thanks to logical properties). Status modifiers match the alert palette so callouts and code samples can speak the same colour language.

Cards

Forms
 
Inputs, labels, and groupings for collecting user data.
 
Form fields
 
Labels, text inputs, textareas, fieldsets and legends — all sized consistently with the rest of the design system.
 
<code class="language-html"><form> <label for="name">Name</label> <input id="name" type="text" required> <label for="email">Email</label> <input id="email" type="email" required class="input-primary"> <label for="msg">Message</label> <textarea id="msg" rows="4"></textarea> <button type="submit" class="button primary">Send</button> </form> </code></pre> 
 
   
 
 
  
 
 
 
 
Accessibility note. Every input must have a programmatically associated <code>&lt;label for="…"&gt;</code>. Group related controls inside a <code>&lt;fieldset&gt;</code> with a <code>&lt;legend&gt;</code>. Mark required fields with <code>required</code> (and a visible asterisk in the label text).
 
 
Status inputs
 
Tint a single input to communicate validation state without rebuilding the form. The status modifier classes pair with any <code>&lt;input type=""&gt;</code> that already has element styling.
 
<code class="language-html"><input type="text" class="input-primary" placeholder="Primary"> <input type="text" class="input-success" placeholder="Saved"> <input type="text" class="input-warning" placeholder="Check this"> <input type="email" class="input-error" value="not-an-email"> <input type="text" class="input-info" placeholder="FYI"> </code></pre> 
 
 
 
 
 
 
 
 
 
 
Accessibility note. Colour alone never carries meaning. Pair <code>.input-error</code> with <code>aria-invalid="true"</code>, an inline message linked via <code>aria-describedby</code>, and a visible icon or text label.
 
 
Fieldsets
 
<code>&lt;fieldset&gt;</code> groups related controls; <code>&lt;legend&gt;</code> names the group. Both inherit Skeletonic's spacing and border tokens automatically.
 
<code class="language-html"><fieldset> <legend>Notification preferences</legend> <p> <input id="email-pref" type="checkbox" checked> <label for="email-pref">Email digest</label> </p> <p> <input id="sms-pref" type="checkbox"> <label for="sms-pref">SMS alerts</label> </p> </fieldset> </code></pre>

Layout
 
Structural primitives — grid, container, header — that frame the whole page.
 
Grid
 
Native CSS Grid since v2.0. <code>.grid</code> sets <code>display: grid</code> and a gap; <code>.grid-cols-N</code> (1–12) generates the column tracks; <code>.col-span-N</code> (1–12) lets a single child span multiple cells.
 
<code class="language-html"><div class="grid grid-cols-2"> <div>Half</div> <div>Half</div> </div> <div class="grid grid-cols-3"> <div>Third</div> <div>Third</div> <div>Third</div> </div> <div class="grid grid-cols-3"> <div class="col-span-2">Two thirds</div> <div>Third</div> </div> </code></pre>

Accessibility note. Visual order should match DOM order. Avoid reordering with <code>grid-auto-flow: dense</code> or explicit <code>grid-row</code> / <code>grid-column</code> shuffling — screen readers and keyboard users follow the source, not the paint.
 
 
 
Migrating from v1.x. The <code>.flex-N</code> / <code>.row</code> flexbox grid is gone. Replace <code>&lt;div class="row"&gt;&lt;div class="flex-6"&gt;…</code> with <code>&lt;div class="grid grid-cols-2"&gt;&lt;div&gt;…</code>. The new system is shorter, uses native CSS Grid, and avoids margin-collapse quirks.

Accordions
 
Zero-JavaScript collapsible disclosure containers leveraging the HTML5 <code>&lt;details&gt;</code> and <code>&lt;summary&gt;</code> elements with native <code>@interpolate-size</code> smooth height transitions.
 
<code class="language-html"><details class="accordion"> <summary>What makes Skeletonic Stylus unique?</summary> <div class="content"> <p>Skeletonic Stylus is a zero-dependency, cascade-layered CSS library engineered for the post-bundler web. It delivers WCAG AAA compliance, OKLCH colours, and 100% native browser baselines in under 7.7 KB gzip.</p> </div> </details> </code></pre> 
 
 
 
 
Accessibility note. Native <code>&lt;details&gt;</code> elements inherently communicate state (<code>aria-expanded</code>) to screen readers and offer full keyboard control (<code>Space</code> / <code>Enter</code> toggle) without needing custom JavaScript event handlers.
